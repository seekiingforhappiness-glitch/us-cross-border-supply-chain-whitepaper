# 建造者透视镜 v2（Builder Console）

> 把系统的**内在设计**与**活世界**，摊开给建造者看。
> 给创始人 Daniel 的独立可视化应用——**零后端**、只读、暗色蓝图风。
> 依据：`docs/control-tower-plan-v0.2.md` 的 V4 决议 + `docs/superpowers/plans/2026-07-14-console-v2-requirements.md`
> （Daniel 对 v1 的验收：审美与「每图一问」对，但深度只到介绍册——**缺关联层 + 实体层**）。

v2 补齐 v1 被点名的两层缺失：
- **关联织网**：把 34 类型 × 53 关系 × 31 动作 × 18 规则织成**可穿梭**的结构（从 Shipment 顺关系走到 SalesOrderLine，点动作看五要素，点规则跳规则档案）。
- **实体下钻**：点进 SHP-SIM-xxx 这一票具体的货，看**全部字段值 + 关系网 + 完整时间线**（里程碑 + 异常 + AI 提案 + 审批 + 处置，含 `caused_by` 连锁标注）。

数据源从 v1 的 `ontology.sqlite` 切到**活世界** `simworld.sqlite`（14 个月连续模拟，含异常谱系 / 连锁 / AI 处置 / 先例 / 账本）。`ontology.sqlite` 降为「验证世界」对照源，仅在规则档案引用其 R/P=1.000 引擎战绩。凡活世界产物在界面上显式标 **sim** 徽标，不冒充真实。

铁律不变：**每个视图回答一个问题**，白话优先，暗色蓝图审美（Palantir Ontology 等距分层图气质），悬停联动，诚实标注。

## 一条龙启动（三步）

```bash
cd apps/builder-console

# 1) 生成数据快照（只读读取 ontology JSON + data/simworld.sqlite；ontology.sqlite 作对照）
python3 export_data.py
#    小 JSON 写 src/data/*.json（进主包）；大 JSON entity.json 写 public/data/（运行时懒加载）。
#    脚本只 SELECT/PRAGMA，绝不写库。会打印各 JSON 体量表（总量 ~9.2MB，<15MB 上限）。

# 2) 装前端依赖（仅首次）
npm install

# 3) 起开发服务器
npm run dev   # http://localhost:5173
```

生产构建与本地预览：

```bash
npm run build     # tsc 类型检查 + vite 打包到 dist/（主包 ~365KB，entity.json 不进主包）
npm run preview   # 本地静态预览 dist（http://localhost:4173）
```

> **为什么必须先跑第 1 步**：`src/data/*.json` 与 `public/data/entity.json` 都是导出脚本的产物，被仓库根 `.gitignore` 的 `data/` 规则忽略（生成物不进版本库）。没跑导出，前端 import/fetch 不到数据。数据变了就重跑 `export_data.py`（改后需重新 `npm run build` 才更新 preview 的 dist）。

## 关联织网 · 交互设计

**不是节点图，是「结构化关联卡 + 穿梭导航」**（上一版被判「节点堆砌没意义」的教训）。左栏 34 类型按 7 业务域分组；选中一个类型，中央展示它的关联卡五块：

1. **字段清单**——每字段带白话 desc，敏感字段（如 Customer.tier）附「受限 · 仅 xx 可见」标注（展示权限层而非隐藏）。
2. **状态机**——迷你 SVG，状态横排、转移画箭头（起态绿、终态琥珀）。
3. **它的关系**——出边/入边分栏，每条是按钮：`关系白话 → 对端类型 · 基数`。点任意一条**穿梭**到对端类型的关联卡。
4. **能对它做的动作**——每个动作按钮，点开展开**五要素**（签名/执行角色/前置/成功效果/失败处理/审计）；冻结区红条。含「主 target」与「次要触碰」区分。
5. **盯着它的规则**——每条规则按钮，点**跳规则档案**并高亮该规则卡。

穿梭示例（验收路径）：Shipment 的入边「分配自哪票货」→ ShipmentAllocation → 出边「供给哪条订单行」→ SalesOrderLine → 点动作 ReserveInventory 展开五要素。

## 实体全景 · 交互设计

类型选中后进**实例列表**（表格，可搜 ID/状态/字段，索引全量、全景详情覆盖前若干条 + hero 邻居）。点一条进**全景页**三块：

1. **全部字段值**——脱敏口径（创始人视角全显，受限字段带标注）。
2. **它的关系网**——出边/入边按对端类型分组，每个关联实例是 chip，点击**穿梭**到那个实例的全景（真实实例间的连接，非类型级）。
3. **完整时间线**——从 `sim_event_log` / `sim_ai_activity` / `resolution_memory` / `shipment_milestones` 拼装，按泳道着色（事件/里程碑/AI/先例），异常带 family·severity 标签，**连锁事件显式标注 `↳ 连锁：由 SEV-xxxx 触发`**。

默认 hero＝SHP-SIM-00055：转船漏接致延误 → 滞箱费（连锁，在其货代账单）→ AI 检测 R1 critical → 提案加急（引用先例）→ 经理审批 → 17 天关闭「有效」——一条完整故事。

|---|---|---|
| entity.json | public/data（运行时懒加载） | ~9.3 MB |
| weave.json | src/data（进主包） | ~184 KB |
| actions.json | src/data | ~42 KB |
| journey / rules / evolution | src/data | 13-19 KB 各 |
| structure / constitution / world / decision_lineage | src/data | 5-8 KB 各 |
| flywheel / ai_activity / meta | src/data | 1-4 KB 各 |
| **合计** | | **~9.2 MB** |

entity.json（活世界全量实例 + 关系网 + 时间线）走 `public/data/` 运行时 fetch，**不进主包**——主包仅 ~365KB，只在打开「实体浏览」时加载一次。

## 诚实口径（重要）

- **数字全部实时取自活世界快照**，不写死统计数字（全局规则 5）。稳定文本（宪法/白话标签/关系名）作者写、数字机器取，两者分离。
- **两世界分开报**：活世界（simworld）报真实触发/运转；验证世界（ontology + data/truth）报引擎 R/P=1.000。不混算——「跑了多少次」≠「判得准不准」。
- **诚实标空**：`llm_calls` 0 条 → AI 账本右账如实标「诚实的空账 · 待生产运转」；采购/准入/寻源域实例未灌入活世界 → 结构层完整可浏览，实例层如实标「活世界暂未覆盖此域」。
- **sim 徽标**：凡模拟产物（先例/账本/运转/世设）显式标 sim，不冒充真实。
- 页面处处标注**数据截至时间**与 `READ-ONLY`；底部状态条常驻活世界透明度。

## 硬约束（已遵守）

- **只读一切**：`export_data.py` 以 `mode=ro` 打开 sqlite，只 `SELECT`/`PRAGMA`。
- **零后端**：构建期消费静态 JSON + 运行时 fetch 一个大 JSON，产物是纯静态站点。
- **四红线零触碰**：本任务只动 `apps/builder-console/`。
- **脱敏**：导出只含 ID、业务数字、状态、事件；无个人信息类字段（customer_name/supplier_name 均为公司名）；权限受限字段附标注。

## 技术栈

React 18 + Vite 5 + TypeScript（strict）。可视化纯手写 SVG/CSS，无重型图表库。跨视图穿梭用轻量 Nav context。中文界面，术语带白话。
