# C1 处置记忆→更好提案：设计提案（§3 候批）

> 2026-07-12 深夜。依据：主干路线图 §3-C1 + 实施手册阶段 1 + 规格 v3.0。批准后按主干交付纪律执行
>（最小纵向切片→无头测试→controller 独立复核四红线→STATUS+决策日志→commit）。

## 目标（一句话）

让每次处置成为下次提案可引用的证据——同类风险再来时，提案自动附"过去 N 次同类案子怎么处理的、
实际结果如何"，把"越用越强"从口号变成看得见的东西（护城河最小闭环）。

## 现状与缺口

action_log 记录了"做了什么"（谁、何时、什么动作），但：①没有"为什么这么做"（决策时看到的影响金额、
AI 建议、参考依据没有归档）；②没有"后来怎么样"（结果与复发未回填）；③没有"按相似情境检索旧案"的回路。

## 最小切片（四件）

1. **resolution_memory 表**（从 action_log+risk_events 派生+关闭时回填）：情境快照（对象 ID/规则类型/
   严重度/影响金额/as_of）· AI 提案（版本戳+正文+引用）· 人的决定（采纳/修改/拒绝+审批人）·
   实际结果（解决耗时/是否复发）· 质量标签。
2. **相似检索（只读工具）**：规则类型精确匹配为主键（不做向量——主干路线图明确），第二维度待裁决（Q1）。
3. **提案增强**：propose 流程附先例区块——"同类 N 次：改期 X 次/加急 Y 次；最相似一案：RSK-xxxx，
   当时选择…实际结果…"。**所有数字运行时从 resolution_memory 现算，可回查核对，禁止缓存或编造。**
4. **DecisionRecord 血缘雏形**：从 C1 起，每次审批记录四件套（世界快照渲染文本+提案版本戳+引用先例+
   决策人）+ 场外依据字段。

## 阶段门 G1（验收）

固定样本证明：任何提案可回放"当时看到什么、引用了什么、人为何改、结果如何"；
**删除/屏蔽某条先例后，系统不得暗中继续引用**（可解释检索的负向测试）；
新增 test_resolution_memory（断言含：数字可回查一致、先例引用可溯源、无先例时如实说"首例"）。

## 四红线（不动）

R1-R18 全 P/R=1.000 不扰动 · 真值 md5 逐字节不变 · maker-checker/FORBIDDEN 一字不改
（检索是只读工具；写 resolution_memory 由动作层在审批/关闭时自动完成，AI 无写入工具）· agent 不越权。

## Daniel 裁决点（三个业务问题）

- **Q1 "同类案子"怎么算像**：延误风险找旧案参考，哪个维度更有价值——同航线（美西找美西）、
  同客户等级（A 客户找 A 客户）、还是两个都要（都要=检索更准但首年样本更稀）？
- **Q2 提案里给几条旧案**：最相似 1 条讲透 + 一行汇总统计（建议，防信息过载），还是 top 3 并列？
- **Q3 质量标签谁打**：专员关闭异常时顺手点一下"AI 建议：有效/部分有效/无效"（每次 3 秒，
  是一致率成绩单和评估集的原料——建议），还是先不打、日后从结果反推（省事但粗糙）？
