## 1. 合流后的统一图景

- **基线 = v0.9.0 主干**：5 场景（延误/费用/准入/采购/仓储）、R1-R18 全 P/R=1.000、34 对象、7 角色、
  对象级 AI 助手（claude_cli 订阅通道 + Opus 4.8，单发合成、无行动能力）、CL1 协调回路 + 协调收件箱。
- **能力主线 = Codex 路线图**（`docs/system-framework-and-roadmap.md`）：
  B 协调可见化（**已完成**）→ **C1 处置记忆→更好提案（合流后第一优先）** → A 信息流入 → C2 对手方情报
  → C3 打法沉淀 → D Edge 度量。Daniel 裁决维持此排序。
- **产品化层 = 本线成果并入主干**，按适用时点归类：
  - **立即适用（C1 期间并行落地）**：运维骨架（心跳外部监控/systemd/计时状态从库派生/`.backup` 备份+每周
    自动恢复演练/回调验签）；评估分级闸门（红线随手跑/全量夜间跑）；冷启动静音策略与通知埋点；
    宪法九条（10c 修正版）；叙事修正（"可以带走但别处用不起来"/"1 人干 3 人的活"/"新专员上手包"）；
    对抗评审机制常态化（每个大版本前重跑，六路提示词在 docs/research/ 各评审文件可复用）。
  - **A 能力时适用**：接入阶梯与介质普查、待确认队列防毒化（专员 15 分钟预算/批量确认/当天回报）、
    断货模型影响公式+滞箱费倒计时、毒信队列、出境白名单摘除闸门（见 §2）、摄入端第三方 PI 摘除、
    事件信封幂等、对外触达=AI 起草人发出+预审模板。
  - **商业化决策点适用（J5 后置包）**：等保二级+测评、生成式 AI 备案评估、SaaS 合同四件套、试点协议
    升级为正式合同、EDI/ICP 许可确认、事件响应卡、保险。**J5 例外（Daniel 已确认）：ICP 备案与
    一页纸试点协议在 A 能力接真实数据前完成。**
- **双轨验证照旧（J4）**：验证轨（Daniel 亲自访谈 8-10 家陌生货主+3 家货代，Mom Test 三问）**不受
  能力排序影响，可立即启动**；构建轨=主干 A 能力对准亲友业务真实数据（按排序在 C1 之后）。
  第 6-8 周汇合裁决三岔路的机制与预写判据不变。

## 2. LLM 通道的合流裁决与护栏

- **主力 = claude_cli 订阅通道**（Codex 线已打通，Daniel 亲批，零 API 费）；provider 接口做实：
  OpenAI/国产模型为备选 provider，国产 provider 适配须真实跑通评估集一次（J1 护栏，Daniel 已确认）。
- **如实标注**：claude_cli 通道的数据处理同样发生在境外（Anthropic 服务）——**出境白名单摘除闸门对它
  同样适用**（发往任何境外模型的 payload 摘除姓名/电话/账号，出境调用留审计日志）。合成数据阶段无此问题；
  **A 能力接真实数据之日起闸门必须已就位**。商业化决策点重审模型选型（Anthropic ToS 对中资实体的
  限制条款见 `docs/research/2026-07-12-adversarial-review-compliance.md` A1——订阅通道的条款风险
  同样存在，商业化前须正面解决，届时国产已备案模型为合规默认的建议重新上桌）。
