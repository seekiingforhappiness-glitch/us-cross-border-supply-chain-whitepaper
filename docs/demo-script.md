# 十分钟演示脚本（v0.5 作品集）

面向：给别人（面试官/同行/合作方）现场演示。与 demo-assertions 的区别：那是验收清单，
这是**讲故事的台本**——每一步配一句"这说明了什么"。

## 准备（演示前 2 分钟）

```bash
cd ~/Desktop/数智供应链
python3 -m datagen.generate >/dev/null && python3 -m pipeline.build_ontology >/dev/null \
  && python3 -m engine.detect && streamlit run app/streamlit_app.py
```

开场白："这是一个参考 Palantir Ontology 理念的供应链运营原型——重点不是界面，
是**对象-动作-权限-审计**这套底层，以及三个业务场景怎么跑在同一个本体上。"

## 第一幕：延误闭环（4 分钟，角色 ops）

1. **风险队列**：指出六种规则的事件混在同一队列（延误/缺文件/停滞/超收/重复计费/计划外）
   → "传统做法是三套系统三个看板，这里是一个本体一个队列"
2. 选 **SHP-2026-0099 的 critical**（RSK-0044 附近）："8/8 收到船期变更事件，系统沿
   船→分配→订单行→客户 的对象图算出：只有 SOL-0188-1 这 500 个充电器会违约，
   同船另一个客户的货不受影响——**行级精确，不是船级拍脑袋**"
3. 指"客户等级"列的 🔒无权查看 → "我现在是物流运营，客户分级不该我看。null 不等于没风险，
   无权是显式的"
4. **派单** → 故意再点一次 → 红色拒绝"已存在非终态任务" → "防重复是动作层的前置校验，
   拒绝本身也进审计"
5. 任务处理台提 **reschedule 08-27** → 切 manager 前先试着自批 → 被拒 →
   "审批权在动作层不在按钮上" → 切 manager 批准 → 指承诺日已回写、行状态解除
6. 切回 ops 关闭 → **审计日志**：完整链 + 刚才所有被拒的尝试 → "失败也是一等公民事件"

## 第二幕：一个本体三个场景（3 分钟）

7. **准入工作台**：选 AC-2026-0031 → "同一批客户对象：下单的客户和申请准入的客户是同一个
   Customer，一条 SQL 能同时取出它的准入案件和延误历史"
8. 切 manager 试批 **AC-2026-0032** → G1 拒绝（critical UFLPA 未核实）→
   "门禁是硬校验：critical 合规、DDP 无 IOR、跳流程，三重门禁谁来都拦"
9. **费用工作台**：选一张 under_review 发票 → 基准对比列 → "账单和费率卡逐行对账"
10. 回风险队列找 **SHP-2026-0009 的 R6** → 读 root_cause："这笔滞箱费源于 ETA 延误 8 天"
    → "**跨场景归因**：费用异常自动引用控制塔的延误事实——这是三个系统共用一个本体
    才可能做到的一句话"

## 第三幕：AI 与工程底座（3 分钟）

11. 终端跑 `python3 -m agent.evaluate` → 22 题全绿 →
    "AI 的不编造、不越权靠架构：审批工具从未注册给它；HTS 税号只能来自合规记录，
    没有就回答'未提供，不做臆测'"
12. 跑 `python3 -m datagen.verify` 指"同种子两次生成逐字节一致" →
    "全部数据合成但带 ground truth，查准查全是真算出来的 1.000，不是自己夸自己"
13. 收尾亮点（诚实工程文化）："项目有一个如实记录的失败 KPI——第三场景边际成本
    目标 ≤25%，实测 52%。拆解后发现业务闭环只要 400 行，贵的是造世界的脚手架。
    **我们选择记失败并修正认知，而不是解释成达标**——复盘 §0-v4 有全文。"

## 常见问题备答

- "数据是真的吗？" → 合成但高保真：ISO 6346 柜号可在 bic-code.org 验校验位、
  SCAC/UN LOCODE/DCSA 事件语义均按行业标准生成，且带 ground truth 供评估
- "和直接用 Palantir 什么关系？" → 学习性复刻底层理念（对象/动作/权限/审计/AI 护栏），
  未用其平台；文档从 v0.1 手册到决策日志完整可溯
- "AI 写的还是你写的？" → 人机协作且有治理：人裁决全部 26 项建模决策并验收每周断言，
  AI 按宪法（AGENTS.md）执行开发，363 条审计里人和 AI 的动作同格式可区分
