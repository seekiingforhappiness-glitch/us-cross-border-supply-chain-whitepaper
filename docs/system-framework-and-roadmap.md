# 系统框架与能力路线图 · 从控制塔到"越用越强"的运营中枢

> 2026-07-09 沉淀。承接 `docs/notes-decision-rights-org-design.md`（决策权/第一性原理）。
> 本文的任务：**先立框架 → 再逐能力压实实施路径 → 最后建/验/交**。原则：不写虚词，每条能力都给
> 定义 / 现状 / 最小切片 / 验证方式 / 守的红线，且可回代码与真实数据核验。

## 0. 定位（一句话）

不是数据看板，不是聊天机器人。是一套 **ontology 驱动的运营中枢**：感知异常 → 完整定位影响 →
起草处置 → 人拍板 → 执行 → **沉淀记忆**，让**整个组织**更完整、不遗漏、一致、可举证，且**越用越强**。
诚实边界：当前跑在高真实感合成数据上，证明方法与能力。

## 1. Edge（可衡量，不是虚词）

**先泼冷水**：edge 不是"AI 更聪明"——谈判/异常判断/关系上，好的老师傅吊打系统。edge 是**系统性的**
（整个组织变强），不是单点天才。每条给一个**可测指标**，否则就是虚词：

| Edge | 一句话 | 可测指标 |
| --- | --- | --- |
| **完整** | 图太大装不进人脑 | 影响定位召回（受影响订单/金额漏判=0）；人工基线 vs 系统耗时/漏判 |
| **不遗漏** | 异常不再丢在某人微信里 | 静默丢失率→0（每异常=带 SLA 的对象）；逾期未跟进可查 |
| **一致** | 质量与"谁当班"解耦 | 处置质量方差↓；关键人离职质量塌方=0 |
| **可举证** | 扯皮变可查审计 | 争议场景（滞港/信用证/关务）审计可查率=100% |
| **护城河（最硬）** | 复利记忆 | 客户专有处置史 + 对手方行为，竞品抄不走，edge 随使用加深 |

**神经系统隐喻**：系统是组织**更好的神经系统**（什么都感知、什么都不忘、路由正确、全程记分）；
人仍是**判断 + 关系**层。**别把"AI 干活"当 edge（人人都会有）——护城河是长在 ontology 上的专有运营记忆。**

## 2. 能力地图

**地基（已建，v0.9.0）**：ontology（34 对象/关系/动作/决策权）· R1-R18 检测（全 P/R=1.000）·
maker-checker 治理 · permission-aware 对象级 agent（Opus 4.8 基座）· CL1 协调回路第一切片。

**路线图（待建，4 个关键能力）**：
- **A. 信息流入 Ingress**：非结构化（邮件/微信/Slack）→ ontology 对象（抽取→提案→人确认）
- **B. 协调回路可见化 + 深化**（承 CL1）
- **C. 复利记忆（护城河）**：C1 处置记忆→更好提案 · C2 对手方情报 · C3 打法沉淀（skills-as-data）
- **D. Edge 度量 Instrumentation**：让第 1 节每条 edge 可测可证

## 3. 每个能力的实施路径（压实）

### A. 信息流入 Ingress
- **定义**：一封邮件/一条微信 → 结构化异常对象（如 shipment 延误、发票争议）。
- **现状**：0——系统靠 seed/detect，无外部入口。这是**FDE 部署的真活**（每客户的邮件格式/微信群/ERP 适配）。
- **最小切片**：一个"入站"适配器：结构化文本输入（先手工/CSV/邮件正文，**不急着接真微信**）→ AI 抽取候选对象 →
  生成"待确认"提案 → **人确认才建对象**。把 maker-checker 延伸到入口（抽取=提案，建对象=确认）。
- **依赖**：LLM 基座（已接 Opus）。
- **验证**：抽取准确率（对一批**真实邮件文本**标注，非自造）；**幻觉=0 建对象**（未确认绝不落库）；确认闭环审计。
- **红线**：未确认不建对象/不动作；抽取错→人改不硬塞；**绝不对幻觉抽取自动建对象**。

### B. 协调回路可见化（承 CL1，最便宜、即见效）
- **定义**：overdue 协调像 SLA 一样冒到运营眼前——"在催谁 / 卡在哪 / 该升级了"。
- **现状**：CL1 建了数据+动作层，**没在 UI 露出**（病根正是"系统看不见"）。
- **最小切片**：协调收件箱视图（overdue 置顶 + 状态 + 催办/升级入口），挂进运营/采购工作台。
- **验证**：AppTest 渲染 0 异常；overdue 正确浮现；数据范围/权限继承。
- **红线**：R1-R18/真值/权限不动（纯呈现层 + 复用 CL1 动作）。

### C. 复利记忆（护城河，分三个真回路；去泡沫：复利的是**数据+记忆**，不是"模型自己变聪明"）
**C1 处置记忆 → 更好提案**
- **定义**：每次处置（类型+情境+选的动作+结果）入"处置记忆"；下次类似异常，提案附"历史：过去 N 次选 X、成功率 Y"。
- **现状**：action_log 有留痕，但无"按相似情境检索历史处置"的回路。
- **最小切片**：resolution_memory（从 action_log + risk 派生）+ "相似历史处置"检索（**先按 rule_id/类型精确匹配，不做向量**）；提案时附带。
- **验证**：检索出的历史确实同类；提案里"历史成功率"数字**可回查 action_log 核对（不编）**。
- **红线**：只读历史、不自动决策；数字**必须可溯源**（防幻觉编造成功率——规则 5）。

**C2 对手方情报**
- **定义**：从历史派生"供应商 X 平均延期 d 天""客户 Y 接受拆单率 z%""某报关行周五慢"。
- **现状**：数据里有 supplier/customer 行为，无聚合画像。
- **最小切片**：counterparty_profile 派生视图（从 shipment/risk/coordination 历史聚合）；检测/提案可用（如"该供应商历史延期→提前预警"）。
- **验证**：画像数字可回查底层记录；**不改检测真值**。

**C3 打法沉淀（学 Hermes 的 skills-as-data）**
- **定义**：把处置打法（如"信用证不符怎么处理"）编码成**可审计的 markdown 打法卡**（不是黑箱权重），人可增删改。
- **现状**：0——处置逻辑硬编码在动作层。
- **最小切片**：playbooks/ 目录（markdown 打法卡：触发条件+步骤+注意）；agent 提案时检索匹配打法卡作依据；人可编辑、即时生效。
- **验证**：打法卡可被 agent 检索并引用；引用可溯源；人编辑后生效。
- **红线**：打法是"建议依据"非"自动执行"；高风险动作仍走 maker-checker。

### D. Edge 度量 Instrumentation（贯穿）
- **定义**：把第 1 节每条 edge 变成能跑出来的数字。
- **最小切片**：edge_metrics 只读报告（影响定位召回、异常逾期率、处置方差、审计可查率）。
- **验证**：数字从真实对象/日志算，不编。

## 4. 排序与交付（build → verify → deliver）

**排序原则**：先"让已建的看得见"→ 再"护城河的最小闭环"（把"越用越强"从口号变可见）→ 再入口（部署价值）→ 度量贯穿。

1. **B 协调可见化**（便宜、即见效，让 CL1 落地看得见）
2. **C1 处置记忆→更好提案**（护城河最小闭环、差异化最强，把"越用越强"做成能看见的东西）
3. **A 信息流入**（FDE 部署真价值，但抽取可靠性要真实数据验证）
4. **C2 对手方情报 → C3 打法沉淀**（深化护城河）
5. **D Edge 度量**（贯穿，随时补，证明 edge 不是虚词）

**每个切片走同一交付纪律**（本项目已固化）：
§3 建模决策 Daniel 亲批 → 最小纵向切片 → 无头测试 → **controller 独立复核守四红线**
（R1-R18 全 P/R=1.000 不扰动 · 真值 md5 逐字节不变 · maker-checker/FORBIDDEN 不削 · agent 不越权）
→ 更新 STATUS + 决策日志 → commit。**每个都是可独立验收的小切片，不憋大招。**

**诚实的悬而未决（承 §9 教训，别在自造世界里自我确认）**：
- A 的抽取可靠性、C1 记忆检索是否**真提升**提案质量——都要**真实数据验证**，不是模拟数据自证。
- 从 Hermes 学**机制**（技能即数据、封顶记忆、人在环），但**别整包搬**——护城河是 ontology + 专有数据，不是通用 agent 框架。
- edge 的可测指标，需要一个**人工基线**对照（没有基线，"更快/更完整"仍是虚词）——这个基线从哪来，未定。

## 5. 一页纸怎么用

- 想知道**为什么值钱** → 第 1 节（edge，带可测指标）。
- 想知道**建什么、按什么顺序** → 第 2、4 节。
- 要**动手压实某个能力** → 第 3 节对应小节（定义/现状/最小切片/验证/红线），照它开工。
- 底层的"为什么这么切角色/功能" → `docs/notes-decision-rights-org-design.md`。
