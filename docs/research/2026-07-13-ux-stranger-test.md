# 三角色陌生人可用性测试·综合报告

> 2026-07-13。三个 Sonnet 执行层 agent 分别扮演完全不了解系统的真实角色，禁读一切文档，
> 仅凭浏览器实操完成场景任务：小林（新入职跟单专员/ops）、陈总（老板/manager）、王姐（财务/finance）。
> 原始三份报告见会话记录。**交叉规则：≥2 人独立撞到=高置信缺陷。**

## 三句最扎心的总评

- 小林："系统里什么数据都有，但没人替我做判断，也没人在我要犯错之前拦一下我。"
- 陈总："界面是给看得懂 delay_breach 和 C1 决策血缘的人设计的，不是给三句话要结论的老板设计的。"
  **愿付数据：现状 800-1500 元/月；修好'给老板看的最后一层翻译'→ 5000+/月。**
- 王姐："对我来说它是一个更聪明的只读报表，不是能闭环干活的工具。"

## 单人发现但级别为阻断的

- **默认展开的风险不是最急的**（小林）：进门自动展开 RSK-0068（$3,250）而列表首位是 RSK-0031（$200,587）——新人会顺手处理错的
- **财务角色断头路**（王姐）：发票对象上 finance"可发起动作：（无）"——但系统文字说"运营/财务经 propose_mitigation 提案"→ 疑似**动作层权限与 UI 导航挂载不同步**（需核对：若动作层允许 finance 提案则纯属 UI bug；若不允许则是权限设计裁决题）
- **首屏无"生意有没有事"的人话结论**（陈总）：五个计数卡答不出"今天要不要紧张"
- 负责人显示"u-ops-cn-lin"系统 ID 而非人名（陈总）；影响金额被截断"20058…"（小林）；锚点链接不随选中对象更新（小林）；审批后无撤回窗口（陈总）

## 修复优先级建议（候 Daniel 裁决）

**P0 阻断修复（四件）**：①财务争议入口（核对权限后：费用工作台内嵌提案表单或任务台挂 finance）②AI 故障人话降级（"AI 暂不可用，以下为数据简报"+启动登录自检）③表单事前检查（有非终态任务→置灰+说明；无权表单→隐藏或禁用）④默认选中联动列表首行（或不默认展开）。
**P1 高价值（六件）**：⑤用户侧文案全面去内部代码（成功="已批准：SHP-xxx 加急空运，多花 $1,135.6，交期保住"）⑥确定性简报默认展开置顶 ⑦"去 XX"引导可点跳转 ⑧术语 tooltip 层（费种/规则/动作码/根因人话化）⑨首屏一句话健康度 ⑩列表搜索/排序/只看异常。
**P2**：人名显示、金额全显、锚点同步、审批撤回窗口、可疑费用汇总视图、"转交给 XX"按钮、移动端简报订阅（陈总点名）。

## 战略级信号（超出 UX 的产品结论）

1. **"最后一层翻译"是杠杆最大的投入**：陈总愿付价差 3-6 倍（800-1500 → 5000+），触发条件只是文案与呈现层改造——与付费代理证据"感知定位决定 5-10 倍价差"精确互证。
2. **"闭环感"是付费分水岭**：王姐"只读报表 vs 能干活的工具"之评，与坟场调研"卖处置闭环不卖可视性"再次互证——角色断头路直接摧毁闭环感。
3. **诊断能力已被陌生用户认可**：王姐（八年对账老手）确认基准差异对比"比我的 Excel 强、每条都能自己验证、我信"——费用稽核的产品价值在真实怀疑者面前站住了。
