# 设计 v2 对抗评审（第 5/6 路）：工程现实视角

> 评审者：独立子代理，扮演"给早期创业公司做尽调的毒舌资深工程师"，任务=证伪。
> 已读：设计 v2 全文、现有原型代码（约 6,900 行）、W7 计划（2,216 行，验收框全未勾）、完备性评审。
> **总评：这份设计对"AI 会越权"的想象力是行业一流的，对"系统自己会坏"的想象力接近于零。
> 治理深度:运维深度 ≈ 20:1——一部有宪法没下水道的城邦。以下每一条都是下水道。**

---

## 一、致命（四周验证期内就会击穿产品承诺，或机制上根本不可能）

**F1. LLM 供应链与部署地互斥，且没进"开放问题"清单（§4）**
单台国内服务器+默认 OpenAI：OpenAI/Anthropic 不对中国大陆提供服务且封锁大陆 API 流量（需核实现状，但设计连问题都没提出）；企微消息含个人信息送境外 API 触发 PIPL 出境（G4 已点名）。工程侧加码：**评估裁判选型、预算闸参数、延迟预算、可插拔适配目标全部下游依赖这个未做的决策**。"可插拔"的架构语言掩盖了"没有一个默认值既合法又连得通"的事实。§15 列了 repo 名却没列这条——排序错了。咬人时点：部署日当天，或第一次安全尽调。

**F2. 系统自身零监控，APScheduler 是单点静默死（§4/§7）**
全部时间驱动承诺（升级链/7×24/催办/断路器）挂在一个进程内定时器上。未回答：进程崩溃谁拉起（systemd 没提）；APScheduler 任务表在内存，**重启即忘**；多 worker 跑 N 遍（重复催办）；**调度器死了，谁、通过什么渠道、多久后知道**。场景：周五晚进程假死，周六货代发"船期改下周三"，无解析无升级，周一老板从客户质问电话先知道——而核心验收是"系统先于人发现异常"。咬人时点：第 2-6 周。

**F3. 接入介质假设未验证：真实群聊可能一半不是文本（§4）**
高频形态：舱单截图、船司官网截图、Excel 拍照、合并转发卡片（复制不出全文）。无 OCR/多模态方案，也没把"仅支持文本+Excel"写成明示假设。**性价比最高的验证：拿设计伙伴真实三天群聊数一数文本/图片/文件比例——半天工作量，决定接入层一半的设计**。咬人时点：bootcamp 第 1-2 天。

**F4. "算清经济账"的分母数据无来源（§4/§7）**
影响金额需要订单主数据、货值、客户等级、罚金条款——1-2 级接入**不产生其中任何一项**，只能靠客户手工建档持续维护，这份数据录入劳役没分配给任何人、没进 bootcamp 清单。场景：第一张延误卡片弹出"影响金额：无法计算（缺订单数据）"，旗舰卖点当场哑火。咬人时点：第一次真实演示。

**F5. 评估闸门与 GTM 节奏互斥（§11 vs §2）**
"全量评估（每例 ≥3 次+扰动+LLM 裁判）全绿才生效" vs bootcamp 驻场每天改十版解析模板——一次全量=数小时墙钟，跑不动。必然结局：闸门第一周被"就这一次"绕过（触发宪法⑨，宪法第一周变废纸）或交付延期。缺**分级闸门**：红线子集随手跑、全量夜间跑。咬人时点：bootcamp 第 1 天下午。

**F6. §8 与 §13 正面矛盾：确认队列到底是不是铁律**
§8"人过目才成事实" vs §13"第 4 周人工确认 ≤30%"——那 70% 算不算事实？算=违反生成验证分离且评估集断粮七成；不算=验收指标无意义。**唯一自洽解：把"解析自动确认"定义为一个自主权域、走 §6 信任阶梯晋升**——设计没写这句话。唯一的实施者是 AI，它会在第一周默默选一边。咬人时点：实施第一周。

**F7. 宪法 10c 在一人公司机制性不可能（§12）**
"创始人改数据走第二人复核"——第二人是谁？照写实施=第一条注定被绕过的机制，而宪法⑨规定被绕过必须回滚复盘——两条宪法互相引爆。诚实写法：降级为"管理员动作全部留痕+每周向设计伙伴披露清单"（做得到的透明）。咬人时点：第一次深夜紧急修数据。

## 二、严重（头三个月内必然造成事故或大返工）

**S1. SQLite 并发与备份机制未定**：三个执行流写同一库文件；WAL 只改善读写并发，写与写仍单写者——长事务导入让飞书回调吃 SQLITE_BUSY；飞书重试+审批不幂等=双重执行。备份：对写入中的 SQLite 直接 cp 会拷出损坏副本，必须 `sqlite3 .backup` 或 Litestream。损坏在第一次真恢复时才发现——最坏时刻。
**S2. 飞书回调验签与审批人鉴权双裸奔**：签名校验/防重放/谁在哪个升级阶段有权批——全未设计。裸奔的回调端点=知道 URL 者可伪造"老板已批准"。与 G2（工作台）是两个独立暴露面。
**S3. 升级计时器的重启语义**：计时器活在调度器内存=每次部署清零：挂起的 P2 永不升级、撤销窗口永不到期、无报错。必须"一切计时状态从数据库派生，调度器只是轮询器"。AI 实施者最易写错的一类代码。
**S4. 无部署/回滚/迁移/staging 章节**：Alembic 未提（而 §3 还有租户自定义字段的动态 schema）；无预发环境，一切变更直接进有真实数据+老板机器人的生产。**评估闸门只管提示词，代码变更零闸门——把最大的变更源放在唯一没有闸门的通道里**。
**S5. 断路器/预算闸跳闸后的降级行为未定义**：预算触发后解析停不停？停=自致停机；不停=装饰。缺降级模式：停富消耗（简报/提案）保命脉（解析+规则告警）+显式通知"已降级"。断路器触发后堆积的提案谁消化，也没写。
**S6. 告警疲劳螺旋无校准数据支撑**："宁高勿低"×"A 客户升级"×时间紧迫三个乘数同向拉高→首周大半 P1/P2 强通知→老板第二周静音→升级链更大声→卸载。校准需要"每条通知→响应时长"埋点，设计没有。"飞书加急电话"依赖套餐版本，未验证就进了矩阵。93% 盲批会以 100% 静音重演。
**S7. 待确认队列就是那个垃圾场**：批量导入一次上百条；无过期策略/批量操作/积压告警/毒信队列（反复解析失败消息的隔离区）/去重键规范（企微时间戳是分钟级，同分钟同文本的两条真实消息会被误判重复）。第 3 周积压 200 条→专员全选确认→评估集从源头污染。
**S8. 解析模板的 few-shot 样本跨租户泄漏（新发现的具体宪法违例机制）**：解析模板实际形态=提示词+该客户真实消息示例；三次法则把它抽象成通用模板时，A/B 家的真实消息片段（含联系人价格）随每次调用发进 C 家上下文=静默违反宪法①。缺硬规则：**进入 SkillAsset 的示例必须合成或脱敏**。
**S9. DecisionRecord 快照的体积与 schema 漂移**：无序列化格式/保留策略/"迁移三次后旧快照还能否被新代码读出"——而这正是它存在的全部意义。低成本解法：快照存渲染后的文本+关键数字，不存对象树。
**S10. 供应商侧 bus factor=1 与 GTM 硬约束**：Daniel 在客户 2 现场的 5 天里，客户 1 的 P1 与宕机同时到达——无人接。**bootcamp 模式成立的前提是产品能无人值守，而 F2 证明它现在不能。**
**S11. "物理上不可跨租户"在单 SQLite 文件里是修辞**：同库文件里的隔离=每条查询记得带 WHERE tenant_id——那是纪律不是物理。真物理隔离的廉价版恰是 SQLite 强项：**一租户一库文件**。设计没选边。
**S12. Streamlit 工作台承载真实客户的时点误判**："接受后换"低估时点：多用户登录/会话/公网暴露在**第一家**客户的专员要账号那天就到期。且字段脱敏若实现在 UI 层等于没实现——必须压在数据访问层，这句话要写进规格。

## 三、建议（可排期）

**A1. LLM 成本量级与瓶颈错位**：解析约每天 0.5-1M token=每天个位数美元（不是问题）；**真正大头是全量评估**（每次发布数百万 token+数小时）和多轮简报。预算闸按"运行/评估"分池；需要 token 计量层，未提用什么记账。
**A2. 模型强制退役**：供应商每 6-12 个月退役旧模型=每年数次被迫全量回归+提示词修复，一人公司年度计划里必须有这项日历劳役。
**A3. §6 与 §8 先例写入矛盾**：§6 L1 把"写先例"列为 AI 自主动作，§8 说先例只由人工审批自动沉淀——一句话修掉，否则实施成前者。
**A4. "继承 W7 M3/M7 设计"是纸不是码**：那是未获批执行的计划文档，新 repo 无一行对应代码。措辞会让未来 AI 会话以为事件信封/outbox 已存在——实施计划必须降级表述为"待实现规格"。
**A5. 恢复演练机制化**：每周自动恢复到临时库+校验行数+结果播报飞书。否则宪法②是签过一次名的空头支票——写备份代码和证明可恢复的是同一个人，正是全文别处都在防的"自检代替验证"。
**A6. 邮件接入（2 级）被写成一行字**：PDF 提单/Excel 附件/HTML 邮件/转发链/垃圾过滤——工作量按"再做一个 1 级"估。
**A7. 事件时区纪律**：聊天文本解析出的"7/15 到港"归属哪个时区无规则；跨日界线 urgency 差一天，第一次误报最伤的是老板的信任。

## 四、技术顾问裁决：先砍三样、先补三样

**砍（挪出阶段 1，不是删除）**：
1. **砍两个 AI 同事只留 ops-agent**：finance/cs 是纯乘数（3 倍提示词/评估集/权限视图/漂移面）；共享运行时照建，"同事=注册表配置"保证以后加回来是配置活。
2. **砍自主权晋升引擎，保留静态矩阵+影子模式+人肉台账**：一致率自动统计/系统提议/自动降级全部建立在"每格样本 ≥30"上——**四周凑不出两个域各 30 样本，这是算术**。第一年电子表格记一致率、创始人手动签发 AutonomyGrant，治理效果一分不少，代码少一半。
3. **砍 SkillAsset 自动起草+重型评估**：解析有真值用确定性断言评（便宜/瞬时/无方差），LLM 裁判只留给自由文本简报；红线集冻结随手跑+全量夜间跑（同时解掉 F5）；提示词头一年手工改。顺带把三通道渲染砍成两条写死的消息：老板卡片+专员队列。

**补（每样都比新功能优先）**：
1. **运维骨架一章——系统必须能叫醒自己的运营者**：systemd 自启；调度器每 5 分钟向外部监控打心跳（UptimeRobot 级现成服务，绝不自建），断了打电话；未捕获异常推飞书告警群；磁盘水位告警；每周自动恢复演练+播报。没有这章，§13 全部验收建立在"系统恰好活着"这个没人守护的前提上。
2. **接入失败语义+介质普查**：毒信队列/重试退避/LLM 不可用时人工录入兜底/粘贴去重键规范；**写实施计划前先做半天的介质普查**（真实三天群聊的文本/截图/文件比例），据此裁决 OCR 进范围还是书面排除。
3. **第 0 号决策：LLM 供应链与数据法域**：国内合规可用的模型选型+数据出境立场写成客户可读的一页（本来就说安全故事是销售材料）。评估裁判/预算闸/延迟预算/脱敏规则全是它的下游。**它不是 §15 的开放问题，是阻塞项。**

候补：部署/回滚/Alembic 章节（S4）；"客户数据资产"对应的导出工具（G5 附议——没有导出，差异化第一条在合同谈判桌上就被戳穿）。

**一句话裁决**：值得批准的是治理与边界（真的好），不值得批准的是它假装运维不存在。按现状实施，系统第一次死在半夜时，产品会用自己的核心承诺——"系统先于人发现异常"——来反讽自己。先砍三样把体量降到一人能扛，先补三样让它死的时候会喊疼，然后这个产品才配得上它的宪法。
